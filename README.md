# GPT-5.6 混用检测器 v4.1.1

这是一个在本机运行的 GPT-5.6 API 检测工具。它不要求你提供可信端，也不会把 API key 写入报告。你只需要填写待测 API，就能同时观察：

- Juice 内部预算指纹是否与申报型号一致；
- 固定行为题的答案分布更像 Sol、Terra 还是 Luna；
- 32/48 是否被粗暴改写成 40 或 40 开头数字；
- 显式 Juice 定义是否可能被隐藏提示覆盖；
- 普通、原生 Codex、无历史和固定 32K 历史之间是否出现差异化路由；
- 请求是否成功、重试、超时或被上游拒绝。

此处下载最新版一键包（git clone暂不可用）：https://github.com/chen-006/gpt56_api_detector/releases

友情链接：[Linux.do 相关讨论](https://linux.do/t/topic/2704354)

概率探针实现参考：[hlwy-ai-checker](https://github.com/hanlinwenyuan/hlwy-ai-checker)

## 重要现实边界：不通过不一定是中转主动掺水

已有实际测试表明，即使账号来自可信号池，请求也可能因官方风控、IP、反代、并发、限流或临时路由而落到不同能力层。相关讨论见 [Linux.do：官方风控与路由现象](https://linux.do/t/topic/2728901)。

- 检测不通过：可能是中转混用，也可能是上游官方风控或临时路由，不能仅凭一份报告直接归责；
- 检测通过：说明本次已启用的固定探针没有发现达到报警门槛的异常，但仍不能排除透明代理或差异化路由；
- 发生争议时：建议降低并发、换时间/IP复测，并让服务方提供对应请求时段的上游号池、请求记录或视频等可核验证据。

## 一分钟上手

Windows 用户解压后双击 `Windows一键启动.bat`。Linux 或 macOS 用户运行：

```bash
sh start_detector.sh
```

浏览器会打开本机页面。按下面顺序填写：

1. `API 地址`：可以填域名根地址，也可以填到 `/v1`；程序会在缺少路径时自动补 `/v1`。
2. `申报模型`：只能选择 Sol、Terra 或 Luna。这是你希望验证的标准型号。
3. `实际请求模型`：真正写进 HTTP 请求的模型名。中转使用自定义别名时填这里，默认与申报模型相同。
4. `API key`：只保存在当前页面和后端进程内存；关闭后台后清除。
5. 选择低、中、高档，确认计划预览，再开始检测。

检测结束后 key 不会自动从当前页面清空，方便继续测试。程序不会把它写入 SQLite、JSON 报告、完整留存或 ZIP。

## 三个默认档位

三个档位不是简单的“少、中、多”请求，而是不同的检测覆盖面。

| 档位 | 适合场景 | 单次计划 | 行为指纹 |
|---|---|---:|---|
| 低 | 快速初筛 | 19 条 | 国家、鸟、b80 各3次 |
| 中 | 常规检测 | 49 条 | 国家、鸟、b80 各10次 |
| 高 | 请求外观与长上下文对照 | 158 条 | 四种请求格式格，b80仅普通无历史 |

高档会组合：

- 普通 Responses + 无历史；
- 普通 Responses + 固定 32K 历史；
- 原生 Codex + 无历史；
- 原生 Codex + 固定 32K 历史。

高档含74条固定32K请求和74条原生Codex请求。计划页会显示稳定的输入 Token 粗估，帮助比较成本；它不是上游账单的精确分词结果。

修改任何内置参数后会自动进入自定义档。自定义档只显示参考匹配度，不产生正式“强烈指向”结论。

## 怎样读结论

Juice 与概率指纹是两条独立证据。

Juice 可能显示：

- `通过`：启用的每个思考档都取得足够的申报型号命中，且没有明确冲突；
- `与申报不一致`：出现只属于其他已知型号的明确指纹，或确定性输出/覆盖探针触发硬异常；
- `证据不足`：至少一个启用档没有足够有效命中；
- `可能非GPT`：Juice 全部无法形成已知 GPT 指纹。

行为指纹可能显示：

- `强烈指向 Sol/Terra/Luna`：当前官方配置通过90%完成门禁，且只有一个模型严格超过该档位阈值；
- `证据不明确`：样本不足、没有模型越线、多个模型同时越线、配置不再是官方档位，或运行契约不匹配。

如果行为指纹强烈指向的型号和申报型号不同，结论区域会变红并列出两者。实际请求模型只是中转别名，不会因为名字不同自行报警。

## 指纹匹配度不是路由概率

页面上的三个百分比表示：这批固定答案的分布与三种可信答案分布的相对接近程度。它不是“请求有多少比例被路由到某模型”，也不是统计学意义上的真实身份概率。

正式强指向线为严格大于：

| 档位 | Sol | Terra | Luna |
|---|---:|---:|---:|
| 低 | 54% | 58% | 77% |
| 中 | 82% | 84% | 97% |
| 高 | 98% | 97% | 99% |

阈值来自 Stage C 中3840条相关记录的随机重组模拟：低档1000万轮、中档500万轮、高档100万轮。低档样本少、波动最大；中档更稳；高档同时比较四种请求格式，最稳定。详细平均值、约99%下界和误判边界可在报告的“现有验证参考与适用边界”中展开查看。

即使所有层都通过，也不能排除透明代理、探针识别、仅对检测请求路由真模型或普通业务请求差异化路由。

## Juice 和确定性探针

Juice 探针只请求待测端。它用多种恒等变形和随机外壳请求原始预算数字，再按申报型号分类。重合值不会被错误地当成混用；只有明确属于其他型号的指纹才触发冲突。

32/48 输出完整性探针的规则很窄：

- 精确返回目标 32 或 48：通过；
- 返回40或40开头的纯数字：判为输出改写，形成硬报警；
- 空字符串、其他数字、解释文字或格式错误：只算无效证据，不触发混用。

Juice 覆盖检测会显式定义一个不属于已知指纹的数字，再检查是否仍被改回已知值。它只覆盖简单的隐藏语义覆盖，不声称能识别所有系统提示注入。

确定性硬异常会在当前持续会话内保留首次证据。行为指纹不会粘住，只看当前滚动窗口。

## 持续监控

持续监控按随机间隔运行，每个周期对每个启用探针独立抽一次概率；命中后才向适用请求格式展开。

| 档位 | 随机间隔 | 每周期期望请求 |
|---|---|---:|
| 低 | 150–210秒 | 约3.5条 |
| 中 | 240–360秒 | 约4.0条 |
| 高 | 480–720秒 | 约14.5条 |

行为指纹按“探针 × 请求格式格”分别滚动；Juice继续按思考档滚动。单次和持续监控共用同一组强指向线，不维护第二套阈值。

## 原生 Codex 与网络代理

普通上游请求默认从现有 Native 抓包模板读取 Codex Desktop User-Agent。`GPT56_USER_AGENT` 环境变量仍可覆盖普通请求。原生 Codex 请求保持模板中的完整 UA、originator、工具上下文和请求形状，不受该环境变量覆盖。

只换 User-Agent 不等于完整原生伪装。要比较完整请求形状，请在高档或自定义档启用“原生 Codex 请求”。

原生 Codex 由 Node 原始 socket 发送。v4.1.1 会在每次请求前由 Python 统一解析：

1. `NO_PROXY` 绕过；
2. `HTTPS_PROXY`；
3. `ALL_PROXY`；
4. `HTTP_PROXY`；
5. Windows 手动系统代理；
6. 直连。

支持 HTTP/mixed 代理端口。PAC-only 和 SOCKS-only 不做猜测转换，请改用代理软件的 HTTP/mixed 端口或系统级 TUN。原生 Codex 仍建议配合 TUN，因为外部代理软件和中转的兼容性差异较大。

## 最近配置与恢复

配置只有在一次检测真正开始后才写入 SQLite。下次打开程序会恢复最近一次已经运行过的：

- 单次/持续模式；
- 档位和自定义修改；
- 并发、间隔、请求格式和上下文；
- 各探针次数、概率和窗口；
- 已导入的自定义探针；
- 安全 API 地址、申报模型和实际请求模型。

尚未开始检测的临时修改不会保存。API key 和完整留存目录不会恢复。点击“新检测”只回到连接页并保留方案；只有“恢复本档默认参数”才重置。

## 完整请求与返回留存

留存默认关闭。开启后必须指定本机绝对目录，检测器会保存无删减请求正文、响应流、时间、请求ID、状态码和必要元数据，但会省略 Authorization。留存内容可能包含长上下文、题面和模型完整回复，应放在受控目录，不要直接公开。

## 探针生成器

生成器用于建立自定义概率探针参考文件。填写可信 API、题面、思考强度和采样数后，它会采集三模型类别分布并计算：

- `S`：模型之间的分布差异，越大越容易区分；
- `D`：同一模型跨时间窗口漂移，越小越稳定；
- `w`：由 S 与 D 得到的参考权重，越大代表“模型差异明显且时间漂移较小”。

自定义探针没有经过发行版同条件验证，导入检测器后只显示参考匹配度，不参与正式硬结论。

## 数据与安全边界

默认报告保存规范化类别、答案哈希、长度、状态码、耗时、重试和脱敏错误。它不保存 API key、Authorization 头或 key 哈希。

应用只监听 `127.0.0.1`。API key 在检测结束后仍留在当前页面和后端内存，便于继续测试；`DetectorSession.close()` 或关闭后台时会清除。
